# 图片目录

图片按“问题 → 单张图”存放。每幅图使用一个独立目录，目录名写成 `图XX_名称`，其中包含：

- `生成图片.py`：推荐运行入口；
- `README.md`：数据来源、运行命令、图注和检查项；
- 同名的 PNG、SVG、PDF：PNG 用于预览，SVG/PDF 用于论文排版；
- `历史版本/`：仅在确有旧稿时创建。

从仓库根目录运行脚本。图片负责人只改 `图片存放/`；模型参数或结果有变化时，先查阅 `交接文档/`。

当前只有问题一的图片，因此这里只建立 `问题1/`。以后出现新图时，再按它实际所属的问题和图名归档。

## Agent 新增图片时怎么建目录

只有收到明确的图片任务并且已经确定图的用途后，才新建目录。不要提前创建空的“问题N”或“图XX”目录。

1. 阅读根目录 `README.md`、`AGENTS.md`、本题模型说明和最新交接记录。
2. 搜索 `图片存放/` 下已有的 `图XX_`。`XX` 使用论文全局图号，不在新问题中重新从 01 开始。例如现有编号到图 04，下一幅论文图使用图 05。
3. 第一次为某个问题作图时，建立 `图片存放/问题N/`；随后建立 `图片存放/问题N/图XX_名称/`。
4. 只把这幅图的脚本、说明和成图放入该目录。两个以上图片共用的函数可放在 `图片存放/问题N/common_plotting.py`。
5. 运行脚本并检查文件齐全，再更新问题目录的图片索引和 `交接文档/`。

目录完成后应是：

```text
图片存放/
└── 问题N/
    ├── README.md                  # 本问题图片索引
    ├── common_plotting.py         # 有共享代码时才创建
    └── 图XX_简短名称/
        ├── 生成图片.py
        ├── README.md
        ├── 图XX_简短名称.png
        ├── 图XX_简短名称.svg
        ├── 图XX_简短名称.pdf
        └── 历史版本/              # 确有旧稿时才创建
```

## 生成脚本约定

脚本从自身位置推导目录，不写死用户名或桌面路径：

```python
from pathlib import Path

HERE = Path(__file__).resolve().parent
PROJECT_ROOT = HERE.parents[2]
OUTPUT_STEM = "图XX_简短名称"
```

- 输入数据从 `建模计算/问题N/输出/`、`提交/` 或任务指定路径读取。官方空白模板不能当成计算结果。
- 输出始终写回 `HERE`，文件主名与目录名一致。
- 一次运行生成 PNG、SVG、PDF。PNG 使用 300 dpi；SVG、PDF供论文排版。
- 脚本不得在仓库根目录、`建模计算/` 或其他图片目录散落输出。
- 随机图固定随机种子。坐标轴、单位、图例和图注中的数值必须与模型及结果文件一致。

## 单图 README 要写什么

每幅图的 README 至少记录：

- 图片用途和论文放置位置；
- 输入文件及使用的字段、时刻或参数；
- 从仓库根目录执行的完整命令；
- 输出文件名和建议图注；
- 已完成的检查，以及仍需谁确认。

## 生成文件怎么管理

- 主目录只放当前推荐版本。论文负责人引用这里的 SVG 或 PDF，预览时使用 PNG。
- 重新生成同一版本时覆盖同名输出，不追加 `_final`、`_new`、`_v2` 等文件名。
- 需要保留旧稿时才建立 `历史版本/`，文件名注明日期或差异，例如 `图05_碰撞边界_20260902_旧参数.png`。README 说明保留原因。
- 先按哈希判断重复文件。内容完全相同的副本不进入主目录；内容不同的文件不能互相覆盖。
- `__pycache__/`、`.mplconfig/` 和临时截图不提交。绘图所需的中间数据由程序负责人放入对应问题的 `输出/`。
- 不改动其他 Agent 正在处理的图片。确需改图时，先阅读本图 README 和交接记录。

## 完成检查

Agent 结束任务前逐项确认：

1. `生成图片.py` 能从仓库根目录运行；
2. PNG、SVG、PDF 与脚本同目录，文件名一致；
3. 没有文件输出到旧目录或仓库根目录；
4. 本图 README 和问题图片索引已经更新；
5. `git status --short` 中只出现本次负责的文件；
6. 回复中列出输入、运行命令、输出路径和待确认事项。
