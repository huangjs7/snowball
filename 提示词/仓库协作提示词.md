# 数模仓库协作提示词

将下列方括号内容替换为实际问题、文件或结论后，直接发送给 AI 使用。AI 只能在指定职责范围内修改；若需改动其他目录，应先列出影响并等待确认。

## 通用上下文（每次任务开头附上）

```text
这是数学建模竞赛仓库，题目为“板凳龙”。三人分工：
- 程序负责人：按需创建的 建模计算/问题N/
- 绘图负责人：图片存放/
- 论文负责人：论文/主稿.tex

请先阅读 README.md 和相关交接文档。保留已有文件，不删除或覆盖未确认内容；不要移动其他职责目录中的文件。完成后报告：修改文件、运行方式、结果位置、需要他人跟进的事项。
```

## 程序负责人：建模与计算

```text
[附上通用上下文]
你是程序负责人。请针对问题[编号]完成[模型推导/代码实现/结果校验]。
只可修改 建模计算/问题[编号]/。该问题尚无目录时，确认已有实际任务后再创建。
要求：
1. 在本问 README 写清假设、公式、符号、参数单位、结论和运行方法；
2. 主入口命名为 solve.py，代码从仓库根目录运行；本问中间文件写入本问的 输出/；
3. 不覆盖 赛题+资料/赛题/A题附件/ 内的原始模板；确认提交的文件移入根目录 提交/，原处不保留同名副本；
4. 对关键结果给出至少一项合理性校验；
5. 在 交接文档/ 新增记录，说明结果版本、供配图和论文使用的结论。
```

## 绘图负责人：生成论文配图

```text
[附上通用上下文]
你是绘图负责人。请为问题[编号]制作[图名]，表达[要说明的模型/关系/结果]。
先阅读 图片存放/README.md 并扫描已有全局图号。确认本图确实需要制作后，在 图片存放/问题[编号]/ 下建立 图[下一个全局图号]_[简短名称]/，不要创建其他空目录。
该目录必须包含 生成图片.py、README.md、同名 PNG、SVG、PDF。脚本从自身路径定位仓库，输出写回本图目录；中文字体在 Windows 下可显示；坐标轴、单位、图例和编号完整；PNG 使用 300 dpi。
主目录只保留推荐版本。旧稿确需保留时移入 历史版本/，注明日期或差异；不要制造 final、new、v2 等平行版本。
不要修改模型结论或论文正文。完成后写交接记录，包含图文件名、图注建议和论文中应引用的结论。
```

## 论文负责人：撰写与整合

```text
[附上通用上下文]
你是论文负责人。请完成论文的[章节名称]，只更新 论文/主稿.tex，不拆出重复章节文件。
只能引用 提交/ 中确认的数据和 图片存放/问题[编号]/图XX_名称/ 主层图片；不要引用 历史版本/。数据或图片未确认时写“待补充”，不要自行编造。
要求：叙述与 建模计算/问题[编号]/README.md 中的符号、假设、公式一致；说明方法、结果、灵敏度或误差分析；把需要程序或绘图负责人确认的事项写入交接文档/。
```

## 最终检查

```text
[附上通用上下文]
请对问题[编号或全部问题]进行交付前一致性检查：逐项核对模型公式、代码参数、结果表、图片标注与论文文字是否一致。
不要直接改动文件。请按“发现的问题 / 证据文件 / 建议修改人 / 严重程度”输出清单；若无问题，也说明核对范围与未覆盖项。
```

## 整理新图片

```text
[附上通用上下文]
请整理问题[编号]的图片文件。每幅图建立 图片存放/问题[编号]/图XX_名称/，把生成脚本、README、PNG、SVG、PDF 放在同一目录。
先按哈希识别重复文件：完全相同的副本移入 历史版本/ 并注明；内容不同的旧稿不得覆盖主版本。同步修正脚本的导入路径、数据路径和输出路径，并从仓库根目录实际运行验证。
不要修改模型、结果或论文正文。完成后给出目录树、推荐引用文件和未能运行的原因。
```

## 接手续作现有图片

```text
[附上通用上下文]
请接手 图片存放/问题[编号]/图XX_[名称]/。先阅读该目录 README、问题图片索引和最新交接记录，确认输入数据与当前主版本。
只修改该图目录及确有必要的本问题公共绘图模块。运行 生成图片.py，覆盖同名 PNG/SVG/PDF；不要另建 final、new 或 v2 文件。
若新版本改变模型参数、数据或图意，先把旧稿移入 历史版本/ 并注明差异。完成后检查输出没有散落到其他目录，更新 README 和交接记录，再报告运行命令、主版本路径及待确认事项。
```
